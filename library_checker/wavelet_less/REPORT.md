## 前提条件

- 構築配列の値は非負で、`A[i] < 2^LOG`。
- `0 <= LOG <= make_unsigned_t<T> のビット数`。`LOG=0` は全要素 0 の場合を追加確認。
- `0 <= l <= r <= n`、配列長は `INT_MAX` 未満（`n+1` の符号付き整数オーバーフローを避けるため）。
- しきい値 `x` は引数型 `T` で表現可能。符号付き型の負の `x` は正常に 0 を返す。

## アルゴリズムの確認

各段の `[l,r)` は「すでに見た上位ビットが x と一致する候補」を表します。`s[h][r]-s[h][l]` がその範囲の 1 の個数なので、`z=(r-l)-(R-L)` は 0 の個数です。

x の現在ビットが 1 なら、0 側の z 個はこのビットで厳密に小さいことが確定するため答えへ加え、1 側へ移動します。x の現在ビットが 0 なら、0 側だけへ移動します。構築時の安定分割により、移動先の区間はそれぞれ`[mid[h]+L, mid[h]+R)` と `[l-L, r-R)` になります。

加算する集合は各段で互いに重ならず、全ビットを処理して残る x と等しい値は加算しません。したがって「x 以下」ではなく「x 未満」の個数になります。非負配列に対する x<=0 の早期 return、および十分な LOG を指定した配列に対する x>=2^LOG の早期 return も正しい処理です。

## 前提違反に対するチェック不足

通常の入力条件での less の誤答は見つかりませんでした。一方、LOG の指定ミスを防ぐ検査は実装されていません。次の 2 点は実際に再現しています。

1. **LOG 不足で誤答:** `WaveletMatrix<int,2>({4}).less(0,1,1)` は `1` を返します。元の整数で数えると `4 < 1` は偽なので `0` です。値 4 には LOG>=3 が必要ですが、コンストラクタが上位ビットの欠落を検出しません。
2. **LOG が型幅を超えると未定義動作:** `WaveletMatrix<uint64_t,65>({1})` の構築時に、UBSan が 64 ビット型の 64 ビットシフトを検出しました。このプローブは通常の有効入力テストとは別プロセスで実行しています。

これらは入力・テンプレート引数の前提に関する問題です。検査の追加やライブラリ本体の修正は行っていません。
